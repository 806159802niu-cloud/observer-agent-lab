# 观察者 Agent V0.1 交付说明

2026-10-30｜负责人：牛畅｜代码位置：`Service_agents/observer/`

## 一句话

观察者现在有一个能跑通、有稳定输出格式、能被其他模块直接对接的版本。它读一段访谈记录，按五项评分口径给出逐项打分、证据原话、不确定性说明和可照抄的改进建议。

## 三条设计约定

1. **评不出就是 `null`，不是 0。** 没有时间戳就不判"是否打断"，也不默认给中间分。这条是为了防止模型在缺数据时硬凑一个分数。
2. **总分由本地算。** 加权与缺项归一化在脚本里完成，不采信模型自报的数字。评不出的项从分母剔除后重新归一化。
3. **`coverage` 比总分更要紧。** 它记录评得出的项占了多少权重。coverage 低说明这段记录本身缺数据，总分再高也不能拿去横向比较。

## 实测结果

对样例记录（4 轮，含一处人工打断标记）跑评估：

- 五项齐全，每项都带理由与引用原话
- "节奏与尊重"判为 `null`，note 写明"缺少时间戳与发言时长"——这正是期望行为
- "问题开放性"判 2 分：开场是二选一加贴标签（"您是不是属于风险偏好型的人？"），转场是诱导式确认（"所以您最终还是选择了效率优先，对吗？"）
- 加权总分 2.53，coverage 0.85
- 建议具体到能照着改，例如把诱导式确认改成"最后决定搬的时候，您心里排在最前面的是什么？"

完整输出见 `Service_agents/observer/tools/samples/eval-01.json`。

## 怎么接

最小接法，一行命令：

```bash
cd Service_agents/observer
node tools/observer-console.mjs eval <访谈记录文件>
```

stdout 是纯 JSON，没有噪音，可以直接管道给下游。消费方先看 `schema` 字段是不是 `cw-observer/eval/v0.1`，不匹配就别解析。

## 与工作台现有 observer bundle 的关系

`apps/workbench/bundles/observer.json` 目前是 mock 版：启发式打分，rubric 只有 id/name/weight 三项，没有"看什么"和"何时无法判断"。

V0.1 这套是真评分。接进工作台时建议：

- rubric 换成 `Service_agents/observer/rubric.json`（那份简版没有无法判断条件，接了会退化成"缺数据也硬打分"）
- 输出格式换成 `output-schema.json`
- mock 模式保留，用于不接模型时跑通流程

## 待确认（需要组长拍板）

1. **反馈时机**：观察者是访谈结束后评，还是每轮都回流。V0.1 按"结束再评"做，实时方案等这条定下来。
2. **评分口径合并**：`docs/design-questions.md` 里有一版四维口径，观察者这边是五项，需要并成一版。
3. **profile 同步范围**：现在只同步了 `headless` 与 `web-app`。工作台接哪个，就同步哪个，动之前打招呼。

## 已知限制

- 评估随模型波动，同一份记录两次跑可能差 0.2 上下，不要拿单次分数给采访者排名。
- "是否打断"依赖时间戳、话轮重叠或人工事件标记。纯文字记录下这一项永远是 `null`。
- 只有 `headless` 与 `web-app` 写入了观察者人格，其余 profile 仍是上游默认。
