# 终端上手小抄

给不常敲命令的同学。只需要记住一件事：**终端永远站在某一个文件夹里，你敲的命令只对它当前站的位置生效。**

## 一、怎么把终端叫出来

| 场景 | 做法 |
|---|---|
| 在 TRAE 里（推荐） | `⌃ + \`` （Control 加反引号），或顶部菜单「终端 → 新建终端」。TRAE 会直接把终端开在项目根目录，省掉 cd 这一步 |
| macOS 自带 | `⌘ + 空格` 搜 `Terminal` 回车 |
| 想直接开在某个文件夹 | 访达里右键该文件夹 →「服务」→「新建位于文件夹位置的终端」（需在系统设置里开启） |

## 二、四条命令，够用了

```bash
pwd          # 我现在站在哪个文件夹？（print working directory）
ls           # 这个文件夹里有什么？（list）
cd 路径       # 走到那个文件夹去（change directory）
clear        # 屏幕刷干净
```

几个好用的简写：

```bash
cd ..        # 往上退一层
cd -         # 回到刚才那个文件夹
cd ~         # 回到自己的主目录
ls -la       # 连隐藏文件一起列出来
```

## 三、跑一场访谈

```bash
# 1. 先走到项目根目录（TRAE 里已在此可跳过）
cd ~/Documents/Parable-cognitive-worker

# 2. 确认站对了
pwd
#   应该输出 /Users/niuchang/Documents/Parable-cognitive-worker

# 3. 确认能看见这几个目录
ls
#   Service_agents  apps  docs  tools  packages ...

# 4. 跑一场，六轮，观察者给提示
node tools/orchestrator/run.mjs --rounds 6 --mode assisted

# 5. 对照版：观察者只记录，不给提示
node tools/orchestrator/run.mjs --rounds 6 --mode baseline
```

参数含义：`--rounds` 是轮数，`--mode` 是模式。想快点先看效果就 `--rounds 2`。

嫌麻烦可以双击 `tools/orchestrator/跑一场访谈.command`，效果一样。

## 四、跑完看结果

记录落在 `apps/workbench/records/`，每场一份 JSON 加一份 Markdown。

```bash
# 看看已经跑了几场
ls -lt apps/workbench/records/

# 在访达里打开这个文件夹，双击 Markdown 就能读
open apps/workbench/records/

# 直接在终端里看最新那场的 Markdown（改成你自己的文件名）
cat apps/workbench/records/assisted-2026-10-30T04-46-23.md
```

## 五、几个能救命的键

| 键 | 作用 |
|---|---|
| `↑` `↓` | 翻出敲过的命令，不用重打 |
| `Tab` | 自动补全文件名，敲一半按它 |
| `⌃ + C` | 立刻停掉正在跑的东西 |
| `⌃ + A` / `⌃ + E` | 光标跳到行首 / 行尾 |

## 六、报错了怎么办

**不要慌着改配置。** 先看最后三行，那里通常写着原因。常见的三类：

1. `No such file or directory` → 站错文件夹了，或者文件名打错。先 `pwd` 再 `ls` 确认。
2. `command not found: node` → 终端没找到 node。执行 `export PATH="$HOME/.local/node/current/bin:$PATH"` 再试。
3. 一大段看不懂的英文 → 全选复制下来贴给我，不要自己猜着改。

## 七、改完代码要留痕（简化版）

```bash
git status              # 看看改了哪些文件
git add 文件名           # 把要交的加进来
git commit -m "说明"     # 记一笔
git log --oneline -5     # 看看最近几次记录
```

提交前记得还原被自动改掉的锁文件：

```bash
git checkout -- Service_agents/*/pnpm-lock.yaml
```
