# Demo 演示说明（可演示版）

> 状态：2026-10-30 跑通。可以现场演示，可以回答追问，还不能交付给外部。

## 一句话定位

三个 Agent 自主跑完一场访谈，观察者逐轮给采访者的提问打分，并指出下一句该往哪儿问。人只做两件事：选一张人物卡，按下开始。

## 怎么跑

```bash
cd ~/Documents/Parable-cognitive-worker
node tools/orchestrator/run.mjs --rounds 6 --mode assisted
```

嫌命令行麻烦就双击 `tools/orchestrator/跑一场访谈.command`。想快速看一眼效果，把 `6` 换成 `2`，四十秒出结果。

对照组（观察者只记录、不给提示）：把 `assisted` 换成 `baseline`。

跑完的记录在 `apps/workbench/records/`，每场一份 JSON 加一份 Markdown。

## 现场演示讲这三点，顺序别换

**一、先看它在干什么。** 终端里会逐轮打印：采访者提问，受访者照人物卡作答，观察者在旁边打分。三个是各自独立的进程，互相看不到对方的内部状态。

**二、再看观察者干了什么。** 每轮输出五项加权分、覆盖度、这一轮有没有拿到新的判断依据，外加一句可以执行的追问方向。它评的是采访者的提问质量，不给受访者这个人下任何判断。

**三、最后看结论。** 结束时算埋点召回率。人物卡里埋了十条关键信息，明确不给采访者看，跑完数一下挖出来几条。这个数把「挖得够不够」从形容词变成了可比的分数。

## 这一场能报出去的数（2026-10-30 实测）

- 六轮完整跑完，逐轮过程分：4.33、4.82、3.82、4.64、3.64、3.45（满分 5）
- 埋点召回 2 / 10
- 隔离自检通过：送给采访者的输入里没有出现人物卡内容
- 观察者第 5 轮判「有新判断依据」，第 6 轮判「无」，信息增量的判断已经能分辨

## 三个一定会被问到的问题

**分是怎么来的？**
`Service_agents/observer/rubric.json` 里五项加权：不打断 0.30、倾听与承接 0.25、问题开放性 0.20、节奏与尊重 0.15、洞察深度 0.10。缺数据的项记 `null`，不当 0 分，加权时重新归一化。

**召回只有 2，是不是说明它不行？**
这是要修的地方，也正是这套东西的价值所在。第 6 轮观察者自己给出了诊断：追问停在「做法、代价」这类抽象概念层，受访者答不出具体的事，并建议改成从具体个案回忆入手，再从个案回推标准。它能指出自己为什么没挖到。

**跟直接问 AI 有什么区别？**
三个进程隔离，采访者看不到人物卡，整场访谈才成立。同一张人物卡可以反复跑，换提问策略、换提示方式，分数能直接比较。这在真人访谈里做不到。

## 现在不能承诺的四件事

- 人物卡是临时草案，文件头写着待组长确认
- 评分口径有两版（design-questions 的四维、当前实现的五项）还没合并，见《观察者评分标准-v2提案》
- 报告还是工程师视角的 JSON 与日志，不是给人读的一页纸
- 停止条件还没做，现在靠 `--rounds` 硬停

## 下一步往哪走

召回率从 2 拉起来是主线。三件具体的事：

1. 把「追问必须落到具体的一件事、一个时间、一个人」这条写进采访者人格或提示规则，改完重跑三场看召回变化
2. 停止条件：观察者每轮输出 `has_new_insight`，连续两轮为 false 就收尾
3. 批量跑与迭代追踪，这是证明「自加强」的唯一办法
