# 观察者评分标准 v2 提案

> 状态：**提案，待团队确认**
> 提出人：观察者 Agent 负责人
> 面向：团队内部对齐口径，以及见律所时的那页评分标准

---

## 00 一句话结论

现在的尺子量的是「问得好不好」，项目真正要的还有「挖到了什么」。v2 改成三层，分开记，不合成一个总分。

---

## 01 问题：纸面要结果，实现测的是过程

把仓库里六处关于「观察者评什么」的定义挖出来，它们分成两派。

### 纸面定义（四处）

| 出处 | 定义 | 问的是 |
|---|---|---|
| `project-brief.md` 流程 2 | 一致性报告：覆盖点、矛盾点、缺失点、重复提问 | 挖到了什么 |
| `project-brief.md` 对象表 | `EvaluationReport`：问题质量、一致性、重复提问、诱导检测 | 混合 |
| `project-brief.md` API 契约 | `{ coverage, contradictions, repeats, score: { relevance, depth } }` | 挖到了什么 |
| `design-questions.md` 观察者 L2 | 认知获取程度：获得多少有效信息、遗漏什么、是否理解决策规则 | 挖到了什么 |

### 过程定义（一处）

| 出处 | 定义 | 问的是 |
|---|---|---|
| `design-questions.md` 观察者 L1 | 诱导性、冒犯程度、相关性、重复程度 | 问得好不好 |

### 实际实现（两处）

| 出处 | 定义 | 问的是 |
|---|---|---|
| `headless/cordis.patch.yml` 人格六条 | 评采访者表现、不给受访者贴标签、看受访者是否被倾听、问题是否开放、打断需有标记 | 问得好不好 |
| `Service_agents/observer/rubric.json` 五项加权 | 不打断 .30 / 倾听承接 .25 / 问题开放性 .20 / 节奏尊重 .15 / 洞察深度 .10 | 问得好不好 |

### 偏移的后果

一位采访者全程礼貌、开放式提问、从不打断，按现在的五项能拿高分，哪怕六轮下来一条核心判断依据都没挖到。

而项目的目标是「问出真东西」。真东西指的是这个人做选择时权衡了什么、什么情况下他会改主意。这类东西，现在的尺子量不出来。

这不是实现做错了。这五项是按 `design-questions.md` 里 L1 那句「如何评价访谈质量」做的，做得没错。是项目后来的目标往「挖到什么」移了，尺子没跟着移。

## 02 v2 三层结构

| 层 | 回答的问题 | 状态 | 实时模式里干什么 |
|---|---|---|---|
| **L1 过程质量** | 问得好不好 | 已有，保留 | 进 eval |
| **L2 信息获取** | 挖到了什么 | 新增，本期重点 | gaps 是 hint 的内容来源 |
| **L3 可验证性** | 挖到的东西能不能用 | 远期，对应项目最终成功标准 | 只在收尾跑一次 |

三层分开记录，不加权成一个总分。

## 03 L1 过程质量（现有五项保留）

沿用 `rubric.json`，权重不变。

| id | 中文名 | 权重 | 看什么 | 什么情况下判为无法判断 |
|---|---|---|---|---|
| `no-interruption` | 不打断 | 0.30 | 受访者没说完时是否抢话截断 | 无时间戳、无话轮重叠标记、无人工事件标记 |
| `listening` | 倾听与承接 | 0.25 | 是否接住对方刚给出的细节继续追问 | 受访者无实质回答，或缺上一轮内容 |
| `question-openness` | 问题开放性 | 0.20 | 是否开放式、是否诱导、是否贴标签 | 该段没有采访者提问 |
| `pace-respect` | 节奏与尊重 | 0.15 | 是否连续追问、催促、替对方总结 | 缺时间戳或发言时长 |
| `insight-depth` | 洞察深度 | 0.10 | 是否追到判断依据与价值取舍 | 受访者尚未给出可追问的素材 |

保留一条硬规矩：无法判断的项写 `score: null` 加 `note` 说明缺什么，计算加权分时排除并按剩余权重重新归一化，不当 0 分。

## 04 L2 信息获取（新增，本期重点）

这一层接的是 `project-brief.md` 里已经写好的 API 契约字段，不用另起炉灶。

### L2.1 覆盖度 `coverage`

**做法：埋点召回率。**

人物卡里埋 N 条关键信息（`key_facts`），明确不对采访者可见。访谈跑完，数一下挖出来几条。

于是「挖掘充分」这种说不清的话，变成「这一场召回 7 / 10」。带 hint 那场召回 7，不带那场召回 4，两个数一摆，观察者的价值不用解释。

同一张卡跑十场，看召回率怎么变化，比任何形容词都有说服力。

### L2.2 缺失点 `gaps`

**判断依据还没问到的那些。** 写法落到具体动作上，例如：

- 「他权衡了哪两样，还没问到」
- 「什么情况下他会改主意，还没问到」
- 「2019 年那次失败的后果，只说了亏损，没说他对人的顾虑」

这一份清单有两个用处。事后给研究员看这一场漏了什么；实时的时候，它就是 hint 的内容来源。

### L2.3 矛盾点 `contradictions`

前后说法不一致的地方。写清哪一轮说什么，哪一轮说什么，差在哪。

### L2.4 重复 `repeats`

同一条信息是否被问过第二次。判据是信息维度，不是字面维度，换了个问法问同一件事，仍然算重复。

### 输出形式

L2 不打分，出清单加一个比率。

```json
"L2": {
  "coverage": { "hit": 7, "total": 10, "rate": 0.70, "missed": ["...", "..."] },
  "gaps": ["...", "..."],
  "contradictions": [{ "round_a": 2, "round_b": 5, "what": "..." }],
  "repeats": [{ "rounds": [3, 6], "what": "..." }]
}
```

不打分的理由是：漏问了什么，取决于人物卡里埋了什么，而人物卡现在还是草案。给一个未定稿的东西打分，分数没有意义。等人物卡结构定稿后再谈 L2 的分。

## 05 L3 可验证性（远期）

这一层对应 `design-questions.md` 最后一句写的项目最终成功标准：**能否预测人物在未见情境中的选择。**

两个判据：

1. 挖到的判断依据，能不能复述成一条规则。例如「他在任何方案下都不会让家族控股权低于 51%」
2. 这条规则拿去预测一个访谈里没出现过的新情境，他的选择被说中了吗

落地需要一个前置条件：人物卡要带 `unseen_scenarios` 字段，也就是几个访谈里没问过、但答案已定的情境。这个字段现在没有，需要跟人物卡结构一起定。

所以 L3 排在 L2 之后。但它决定了这套系统最终能不能卖出「挖到真东西」这个价值，不能一直不做。

## 06 为什么不合成一个总分

两种情况会给出完全不同的反馈：

| | 过程分 | 召回率 | 这是什么人 | 该给什么反馈 |
|---|---|---|---|---|
| A | 高 | 低 | 很会聊，没挖到东西 | 教他怎么往判断依据上追 |
| B | 低 | 高 | 问得生硬，拿到了料 | 教他怎么问得让人愿意说 |

合成一个数，A 和 B 的分数可能一样，反馈却完全相反。分开展示，两种人各自拿得到该改的东西。

报告上就写三个数加一句话画像：

```
过程质量 3.4 / 5
信息获取 7 / 10
可验证性 待评估（人物卡定稿后启用）
画像：提问克制、不打断，六轮里四次停在外围事实，没有一次追到他真正在权衡什么。
```

## 07 实时模式下三层各干什么

已经定了：观察者实时输出分两层，`hint` 回流给采访者，`eval` 只进记录不回流。三层各自的落点：

| 层 | 进 hint 吗 | 进 eval 吗 | 说明 |
|---|---|---|---|
| L1 过程质量 | 不进 | 进 | 技巧分不该当场告诉他，会变成照着评分表演 |
| L2 缺失点 gaps | **进** | 进 | hint 的内容来源，只给方向不给原句 |
| L2 其余三项 | 不进 | 进 | 矛盾点、重复适合事后看 |
| L3 可验证性 | 不进 | 收尾跑一次 | 依赖整场信息 |

hint 只给问题类型和追问方向，例如「受访者停在结论了，追一次他当时的判断依据」。写出可直接照抄的问句，采访者就会照抄，分数变成观察者的。

## 08 两套口径怎么并

`design-questions.md` 里的四维和现在的五项，不是替代关系，是分层的。建议这样落：

| 四维 | 落点 |
|---|---|
| 诱导性 | 并入 L1 `question-openness` |
| 冒犯程度 | 并入 L1 `pace-respect` |
| 相关性 | 落进 L2（问的东西跟议题有没有关系） |
| 重复程度 | 落进 L2 `repeats` |

这样四维和五项并成一版，不用二选一。

## 09 落进 rubric.json 的结构草案

```json
{
  "version": 2,
  "layers": {
    "L1": {
      "name": "过程质量",
      "scored": true,
      "scale": { "min": 1, "max": 5 },
      "items": [ /* 现有五项，权重不变 */ ]
    },
    "L2": {
      "name": "信息获取",
      "scored": false,
      "note": "人物卡 key_facts 定稿前不计分，只出清单与召回率",
      "fields": ["coverage", "gaps", "contradictions", "repeats"]
    },
    "L3": {
      "name": "可验证性",
      "scored": false,
      "enabled": false,
      "note": "依赖人物卡 unseen_scenarios 字段，定稿后启用"
    }
  },
  "output": {
    "realtime": { "hint_from": ["L2.gaps"], "eval_records": ["L1", "L2"] },
    "final": { "records": ["L1", "L2", "L3"] }
  }
}
```

## 11 这条尺子怎么验收

验收标准不是跑通，是三个人认可。

拿一份真实访谈记录，出一份报告，找三位律师分别看。他们觉得「这个分数说得对」，尺子就成立。他们说不出来的地方，就是还要改的地方。

跑通的 demo 证明的是流程可行，律师的点头证明的是尺子可信。两件事都要有，后者更难。
